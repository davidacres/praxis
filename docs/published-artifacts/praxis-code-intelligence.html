Architecture

One owner process per user holds the index. The desktop app, the command line and every agent's MCP bridge talk to it over a private socket (a current-user named pipe on Windows) with a random token. Language analysis runs in-process for C# and in a Node sidecar for TypeScript. Embeddings come from a pinned local ONNX model.

How a repository is indexed

Registering a folder starts a durable job. Each stage below runs in order, and a later edit re-runs only what changed.

  1. Scan

    Walks the folder, honours .gitignore, and skips node_modules, bin, obj and dist. Limits: 25,000 source files, 256 MB of source and 50,000 symbols per repository.

  2. Analyse

    C# projects are analysed with Roslyn from a passive project manifest; it never builds or restores anything. TypeScript and JavaScript go to the sidecar, which opens every tsconfig project and streams back one record per line. Imports of a workspace package resolve to its source, not its compiled .d.ts, and <Component /> usage counts as a call.

  3. Publish

    Symbols, call and type edges, source locations and the full-text index are written in one transaction. That raises the repository's generation and query epoch together, so a reader always sees one consistent snapshot.

  4. Embed

    Each symbol's name, signature, documentation and a bounded source excerpt become up to four 384-dimension vectors. They are committed every 1,000 symbols, so coverage climbs during the build. A first build stays inactive until the final commit, so search never uses half a model.

  5. Watch

    A file watcher and a one-minute safety reconcile catch edits. Changed symbols are republished and re-embedded. Unchanged vectors are reused, never rewritten.

How search ranks results

search_code runs several retrieval channels and merges their rankings with reciprocal rank fusion (RRF). Exact name matches always come first.

exact · always first

Exact name

The query equals a symbol's name, qualified name or signature.

weight 4

Lexical

SQLite FTS5 with BM25 over names, signatures, docs and descriptions.

weight 1 · floor 1

Vector

Cosine similarity against the bge-small embeddings. Finds code described in different words.

weight 0.5

Alias

Phrases a team has attached to a symbol, matched exactly.

score(symbol) = Σchannel weightchannel ÷ (60 + rankchannel)

Lexical matches outweigh vector matches four to one, because keyword hits are usually right when they exist. That has one failure: when ten weak keyword hits exist, a paraphrased question whose answer only the model finds never reaches the first page. Search plan 8 adds a vector floor: the best vector candidate always takes the tenth place if it ranked lower, and the candidate it displaces moves to the next page.

The eleven agent tools

Every tool is read-only and returns evidence: source paths, ranges, content hashes and the index generation the answer came from. Static call edges show what code can call, not what it does at runtime.

Access and setup

Grants decide what leaves the machine. Indexing is entirely local. Tool results go into an AI provider's context, so each repository is granted to a named client (for example claude-cli). The owner re-checks the grant's root and nonce on every query, and moving or unregistering a repository revokes it.

Inside Praxis it is automatic. An agent session started on a folder registers it, grants that provider, and receives a code_intelligence MCP server scoped to the folder.

For Claude Code in a terminal, one MCP server serves every repository granted to it. Connect each repository once:

npm run connect:code-intelligence -- /path/to/repo

It registers the folder, grants claude-cli, waits for the index, activates the semantic model if it is downloaded, and adds the code-intelligence server to Claude Code the first time. In a session, list_repositories shows what is available, and every tool takes a repository name.

npm run connect:code-intelligence -- --list
npm run connect:code-intelligence -- --disconnect /path/to/repo

Freshness and consistency

  • Generation counts structural publications. Query epoch moves on anything that changes results: publication, stale marking, a model switch or newly ready vectors.
  • Paging cursors carry the epoch and expire only when results could differ. Background bookkeeping, such as the one-minute reconcile, no longer invalidates them.
  • Source reads verify content hashes. A file changed since indexing fails closed instead of returning text that no longer matches the evidence.
  • If the model is missing, hybrid search falls back to keywords with a warning. Vector-only search reports MODEL_UNAVAILABLE.

Limits and open work

  • All performance figures come from one 12-core Mac. The 8-core, 16 GiB reference machine is unmeasured.
  • Real agent adapters (Claude Code, Codex, Copilot) are exercised, not yet formally qualified.
  • Files outside any tsconfig, such as Playwright specs, get declarations but no call graph.
  • The repository limit is 50,000 symbols; Praxis already uses 80% of it.
  • The TypeScript compiler process peaks near 1.3 GB while analysing a large monorepo.
  • Data flow through general delegates is not resolved, and NuGet package names are not inferred.
