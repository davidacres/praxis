What the interface claims

01 – 02
01
High impactEffort: S

The Overview shows three sessions and says there are none

Under Active AI sessions, three cards render with “Ready” status pills, progress dots and sparkline bars — the exact visual grammar of a real session. Directly beneath them sits the line “No active sessions yet.” The panel asserts both things at once, and this is the first screen a new user meets.

// overview-dashboard.png — one panel, two claims
3 cards styled as live sessions (status pill + progress track + bar chart)
1 empty-state line: “No active sessions yet.”
// the cards are promotional copy wearing data chrome

It went wider than one panel. Two more places on the same screen invented figures and drew them as data: the project card's progress meter was 42 + index * 15, a percentage derived from the row's position in the list, and the board card's “views” count was index + 3. In a delivery tool, a reader who finds one invented number has no way to trust the rest.

Fix — done

The three cards are replaced by one empty state in the shape the sibling panels already use: one claim, one sentence saying what a session is, one action. Both invented meters are gone rather than re-based, because nothing in that component knows a project's real progress or a board's real view count. SessionCard's 35/55/78 stays — it encodes real session state rather than inventing a figure.

02
High impactEffort: S

“Work progress” draws a distribution as if it were progress

Replaced with one bar through the pipeline: each segment's width is the stage's share of the work, and the colour ramps from muted at the first stage to the accent at the last — so weight on the left reads as “not started”, weight on the right as “done”. The heading states the real percentage. Then: On a brand-new project, Backlog renders as a full accent bar directly beneath a heading that promises progress and a counter reading 0/5 complete. The bar is a distribution — five of five items sit in Backlog — but it is drawn in the same language as a completion bar. A full warm bar reads as “nearly done” when it means “nothing started”.

Specimen · today, and the correction

Backlog5

Done0
One stacked bar — position carries the meaning
Backlog 5 Discovery 0 Done 0
Fix — done

Collapse the six rows into one stacked bar running Backlog → Done, so left-to-right position carries the meaning and only the Done segment takes the accent. Filled then always means finished.

Legibility and access

03 – 05
03
High impactEffort: M

The type scale has collapsed into a continuum

Twenty-nine distinct font sizes appear in theme.css, including 7px, 7.5px, 10.5px, 11.5px and 12.5px. 74 declarations of real UI text sit below 10px. At those sizes type is texture, not information — and half-pixel steps mean the scale carries no hierarchy a reader can learn.

Correction. An earlier draft of this page counted 102. Twenty-eight of those live inside the scale-model mockups — praxis-preview-*, project-preview-*, the project-type picker and the Look cards — which draw the app at roughly a fifth scale. Their 4–6px text is a drawing, not something anyone reads, and lifting it would wreck the illustrations. The real number is 74.

46× 9px   28× 8px   12× 5px   8× 7px   6× 6px   1× 4px

Everything above 11px in this specimen is a real string from the board card and the activity feed. The four red rows are sizes the app ships today.

Fix

Done. Seven steps, not six: 11 · 12 · 13 · 15 · 18 · 22 · 30. A six-step scale jumping 11 → 13 → 15 would have erased the 12px band that 120 declarations sit in — this app runs denser than the generic scale assumes. 510 declarations now read from a token, every readable-UI size is 11px or above, and the mockups keep their literals on purpose. The 34 heading literals at 14px and up are a deliberate second pass.

04
High impactEffort: S

Keyboard users get less than mouse users

The stylesheet strips focus outlines 26 times and restores a :focus-visible ring 15 times, while styling :hover 91 times. The net effect in a tool built for developers — people who live on the keyboard — is that pointing is rewarded six times more often than tabbing, and in places the focused control is invisible.

Specimen · press Tab to move between these
Outline stripped — today
Focus ring restored

Tab into the pair. The first button gives no indication it is focused; pressing Return would stage a file with nothing on screen saying so.

Fix

One global :focus-visible ring defined on the token system, then delete the 26 blanket outline: none resets. It is close to a find-and-replace and it is the cheapest accessibility win on this list.

05
Medium impactEffort: M

Twenty-three native OS dialogs interrupt the app

All 23 native dialogs are gone. useDialogs() renders confirm / prompt inside the app's own modal surface and returns a promise, so a call site still reads if (!(await confirm(…))) return;. The two that collected data — a branch name, a repository URL — are now real fields that validate as you type. Then: They are unstyleable, ignore every theme you ship, and block the renderer while open. Two of them collect text input through window.prompt — a branch name and a repository URL — which means the two moments where a typo has real consequences are the two moments with no validation, no autocomplete and no visible context.

// renderer/src — window.confirm | prompt | alert
23 total across 8 files
git/GitGraphPage.tsx   window.prompt('New branch name')
git/GitGraphPage.tsx   window.prompt('Repository URL')
git/GitDiffWorkspace.tsx   confirm('Discard this change… cannot be undone')
Fix — done

You already have a dialog system carrying the project wizard and Settings. Route the destructive confirms through it, and turn the two prompts into real forms — the branch-name field can validate against existing refs as you type.

Density and hierarchy

06 – 07
06
Medium impactEffort: M

The Git toolbar is a wall of equally-weighted verbs

Pull and Push moved to the header beside Refresh. The five branch verbs and Pop stash are behind one Branch ▾ menu scoped to the selected branch, with Delete one deliberate step in. The toolbar is a single row again, so the height cap and scroll it grew when it wrapped to four are gone. Then: Nine branch and remote actions sit in one row at identical weight — Branch, Checkout, Rename, Delete, Merge into current, Rebase current, Pull, Push, Pop stash — joined by Compare, Merges only and Smart visibility. At 900px they wrap to four rows and push the commit graph out of view entirely. Delete is tinted red, but it is still one of nine siblings a mis-click away.

// git-graph-narrow-reduced-motion.png @ 900×650
toolbar rows: 4   controls: 13   visible commits: 4
// hourly actions (Pull, Push) rank equal with Rebase and Pop stash
Fix — done

Promote the two you touch hourly — Pull and Push — into the header beside Refresh. Collapse the branch verbs into a single Branch ▾ menu scoped to the selected branch, where Delete sits behind one deliberate step. Rebase and Pop stash go to overflow.

07
Medium impactEffort: S

One accent colour is doing three unrelated jobs

Added --tone-progress, a cool in-flight blue, and pointed the board and pipeline lanes at it — a running stage now carries a blue edge, clearly not the orange Approve button. The accent is the brand mark and the one primary action; status has its own scale. Then: The same warm orange marks the brand, the single primary action on a screen, and in-progress or backlog status. When a colour means three things it stops being a signal, and the eye can no longer use it to find the one button that matters on the page.

Specimen · one hue, three meanings
Brand mark
Praxis wordmark, app icon
Primary action
New session, Attach folder
Status: in progress
Board lane, momentum bars
Fix — done

Reserve the accent for “the one action here”. Give status its own scale — a cool hue for in-progress, green for done — and let the brand mark carry the warm orange alone. Semantic colour and accent colour should never be the same value.

Flow and findability

08 – 10
08
Medium impactEffort: M

Twenty-nine empty states, nearly all of them passive

The inspector empty states now say what the pane is for rather than only naming what wasn't selected, and the “not available yet” placeholder carries a way out. Empty states can carry one explanatory line and one action. Then: The house pattern is “Select a thing to see its other thing” — stage, run, work item, designer item, agent or skill, connection. Each describes the void rather than offering the way out. The Overview’s “Create project” state is the exception and the model: it names the action that fills the space.

// distinct empty-state copy, renderer/src
“Select a stage to edit it.”
“Select a run, or start one.” ← names an action
“Select a work item to see its details.”
“Select an agent or skill to see its runtime.”
// 29 empty states; most stop at the description
Fix — done

Give every empty state the verb that fills it, the way “Select a run, or start one” already does. Where nothing can be created from that pane, say what the pane is for rather than what the reader has failed to select.

09
Medium impactEffort: L

A keyboard-first tool with no command palette

⌘K opens a flat index over projects, boards, sessions, agents, skills, workflows and settings, built from state the shell already holds — arrow keys, Enter, Escape. Navigation only for now; each entry reuses the same navigate() the sidebar uses. Then: Praxis nests projects → boards → issues → sessions → agents → skills → workflows → runs, plus sixteen settings pages, and ships seven keydown handlers with no global palette. Every destination is a mouse trip through the tree. This is the largest perceived-speed win available, and it reads mostly from state App already holds.

// renderer/src
addEventListener('keydown'): 7
command palette / ⌘K: none
// navigable entities: projects, boards, issues, sessions,
// agents, skills, workflows, runs, 16 settings pages
Fix — done

⌘K over one flat index built from projects, boards, agentSessions, workflowsByProject and the agent catalog — all already in App. Ship it navigation-only first; commands can follow once the surface earns its place.

10
Medium impactEffort: S

Settings is sixteen flat peers, weighted toward appearance

Sixteen flat entries became four sections — Workspace · Appearance · AI & agents · Integrations & tools — with Overview loose on top. Themes is now one of three in one of four groups, not three of sixteen. Then: Themes, Looks and Surfaces are three separate entries — 19% of the settings surface — sitting at the same level as Jira, AI Provider, Agent Runtime, MCP Server and Delivery. The shape of the list tells a new user that appearance is three times more important than connecting their tracker.
