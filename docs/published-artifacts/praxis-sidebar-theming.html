Praxis Sidebar Theming

Praxis Desktop · Appearance

The left panel gets its own theme

Right now the workspace sidebar is bolted to the board area's light/dark mode — change one and the other follows. This page mocks up letting the left panel hold its own mode, tint, elevation, or premium material, the way VS Code keeps its side bar dark over a light editor. Every window below is a CSS rebuild of the real sidebar using the exact token ramps from theme.css.

Accent

Today

The sidebar follows the app

One mode setting drives the whole shell. On a light theme the nav is light; on a dark theme it's dark. There's no way to keep a calm dark rail while you read tickets on a bright board.

Option — independent mode

Dark nav, light workspace

The panel pins to dark while the board stays light. The nav recedes, the content you're actually reading stays bright, and the accent still ties the two together. This is the highest-contrast option and the one VS Code users will recognise.

Option — accent tint

A branded surface

The panel keeps the app's mode, but its fill picks up roughly 8% of the accent hue and its hairlines lean the same way. Enough to read as “ours” without turning the nav into a colour block. It tracks the Violet / Blue switch above.

Option — elevation

Raised, not sunken

Today the panel sits a shade below the board. Flip the depth: same palette, but a lighter fill and a soft shadow down its right edge so the rail reads as floating above the content instead of tucked under it.

Premium styles — surface packs

The material layer, on the panel

Surface packs are Praxis's premium material axis (data-surface). A pack sets only --surface-* properties — a tint wash, an edge glow, a grain texture, a watermark motif — never a colour, so it composes over any theme. The panel already reads them: --surface-panel-tint-layer as its fill wash, --surface-accent-glow as its shadow, and the grain / watermark on its ::after / ::before. Parchment is the default Praxis look.

Build

What it would take

  • A new attribute axis on the shell root — data-sidebar-mode (match / light / dark) and data-sidebar-surface (flush / raised / tint) — sitting alongside the data-mode and data-accent axes already documented at the top of theme.css.
  • .pane-sidebar already paints its background from a single token, so a scoped token override on that one pane is additive — no component rules change and the blast radius stays one selector wide.
  • One control in Settings → Themes: a “Left panel” segmented — Match app / Always dark / Always light / Accent tint — persisted in settings.appearance and pushed live, the same path showBrandArtwork already rides.
  • The Themes gallery preview card gains a second swatch, so a packaged theme can ship its own panel treatment.

Mockups reconstruct renderer/src/app/Sidebar.tsx with the token ramps from renderer/src/theme.css and the pack values from renderer/src/surfaces.css / settings/surfacePacks.ts. Grain and watermark motifs are approximated with inline SVG in place of the shipped WebP tiles. Not screenshots — a faithful CSS rebuild, so hues, spacing, and material track the app.
