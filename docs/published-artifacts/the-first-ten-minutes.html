AThe walk today

Nothing here is broken. It is thorough, honest, and slow — and it ends where a first-time user has the least ability to act.

  1. Splash

    Up to 7.8 seconds of brand animation on every launch, skippable by clicking, skipped entirely under reduced motion. A returning user pays it too.

  2. “Give your work a home”

    A form asking for a workspace name, description, and storage folder — a named container demanded before the user has a single thing to put in it. The Skip for now button quietly concedes the concept hasn't landed yet.

    a speed bump with weak justification
  3. “Workspace ready — Start building”

    An interstitial between the workspace form and the project wizard: Create New Project / Create from existing folder / Continue with Empty Workspace. It exists only to bridge two screens.

  4. Wizard step 1 — Choose a project type

    Four planning models with illustrative mini-boards: Software, Product, Research, Experiment. This step earns its place — it changes everything downstream.

  5. Wizard steps 3–5 — brief, plan, tool access

    “Shape the brief” shows six sections, every one marked SKIPPED with an empty radio — the user is asked to opt in to structure they can't yet evaluate. Then “Set up the initial plan”, then “Choose tool access” (“Project-board tools only” vs alternatives a first-timer has no basis to weigh).

    configuration wearing an onboarding costume
  6. Wizard step 6 — Review and create

    “Confirm exactly what Praxis will create”, then a manifest: 0 brief sections prepared, Praxis only — no local folder, 5 starter tickets, No AI session starts during project creation. It reads like a build log, and the “0 brief sections” line is a small self-own right after the user skipped that step.

  7. Project home

    The first real screen: WORK ITEMS 5 · 0 complete, BRIEF 0/6, SESSIONS 0, AI STEPS 0; the right pane's brief is 0/7, all unanswered; “No board is linked yet.” The funnel ends and the user is alone with a dashboard of zeros.

    the landing is emptier than the runway

BShorten the runway

1
Effort: M

Let the first project create the workspace

Getting Started's first-run screen is now Create your first project — New project / Create from an existing folder, with “Name a workspace first” and “Skip for now” as links. Picking a project creates a default My workspace behind the scenes.

NowName a workspace → “workspace ready” interstitial → then start a project.
ProposedThe first project creates a default workspace (“My workspace”, renameable). The user names the project. Workspaces are introduced as a concept only when a second project appears.

Removes two screens and a concept the user isn't ready for. The multi-workspace switcher, the Open workspace file path, and the recents list all stay — they just belong to the returning user, not the first-run one.

2
Effort: M

Three steps for a first project, six behind a toggle

A create-mode wizard now runs three panels by default — type, name, review. Brief, plan and tool access take their recommended values and move to the project home; an Advanced setup checkbox on the type step restores all six. Existing-folder mode is unchanged.

NowType → name & locate → brief → initial plan → tool access → review. Six steps, several of them configuration.
ProposedType → name → review. Brief, plan and tool access take their recommended defaults and move to the project home, which already surfaces the brief as BRIEF 0/6 for the user to fill when it matters. An “Advanced setup” switch on step 1 restores all six.

A first-time user has no basis to choose “Project-board tools only” over its alternatives, or to decide which of six brief sections to skip. Deferring those isn't hiding them — it's putting them where the user can make the call with context.

3
Effort: S

The brief should arrive filled, not skipped

The recommended brief for the chosen type is included and drafted by default; each section is still deselectable and rewritable. Review reads 6 brief sections drafted instead of 0 … prepared.

NowStep 3 shows six brief sections, each marked SKIPPED. Review then says 0 brief sections prepared.
ProposedThe recommended set for the chosen type is pre-selected and pre-drafted (the guided-brief variant already proves this is possible). “Continue” produces a real brief; review says 6 sections drafted.

An empty default asks the user to build structure they don't understand yet. A filled default they can edit gives them something to react to — and removes the “you did nothing” note from the review screen.

CLand on momentum

4
ActivationEffort: M

End on an action, not a manifest

A project with no sessions opens with a Get Started strip above the metrics: a three-step checklist and one primary Start a session button that opens the New Session composer scoped to the project. Dismissible per project.

Now“Review and create — Confirm exactly what Praxis will create”, then a spec sheet, then Create.
ProposedKeep the summary, but make Create land on the board with one action lit: Draft the brief with an agent, or Start a session on the first ticket. The funnel's end becomes the product's start.

The whole product is “turn a ticket into visible progress.” Right now the user reaches that capability by finishing a form and then hunting for where to begin.

5
ActivationEffort: M

A stateful three-item checklist on the project home

Shipped together with #4 as the same Get Started strip — the checklist (Project created · Brief drafted N/M · Start your first session) and the lit action, on the screen the funnel ends on.

NowThe real activation checklist — Create project · Connect a tracker · Start an AI session — lives on the Overview's starter strip, a screen you only reach if you skip project creation.
ProposedMove it into the project home as a dismissible checklist that tracks completion, and let it drive the user to Connections and AI Provider — the two setups onboarding never mentions.

Replaces the four zero-cards on the landing screen with one thing that visibly progresses.

6
ActivationEffort: M

“Explore a sample project” from the first screen

Answered differently. A pre-seeded demo project is a diorama — it shows what populated looks like but teaches nothing about operating the app, it is throwaway data the user then wants to delete, and it needs a runtime seeding path that does not exist. With setup now three steps landing on a Get Started strip, the cost it hedged against is largely gone. Shipped instead: a short walkthrough over the user’s real project — four stops ringing controls the shell already renders, offered once after the first project and replayable from “Take a tour”. The ring never takes pointer events, so the highlighted control stays clickable.

NowA prospect's only path in is the workspace form and the six-step wizard. Demo content (Application Board, Operations Board, starter tickets) exists but is never offered.
ProposedOne click from Getting Started into a populated project: a real board, a finished AI session, a written brief. Evaluate first, set up second.

The highest-leverage single addition for someone deciding whether Praxis is worth the setup. The data is already seeded — this is a route to it, not new content.

DPolish

7
Effort: S

Charge the splash once

StartupSplash gained a brief mode — the finished wordmark, a short hold, a fade, about a second. App turns it on once the profile has been past Getting Started. The full crawl still plays on first run and on a replay from What's New.

NowUp to 7.8s of animation on every launch, for every user.
ProposedFull splash on first run — the brand moment. After onboarding completes once, a 400ms fade or nothing. The code already carries splashReplayKey and reduced-motion handling; this gates on one flag.
8
Effort: S

Make the structure preview answer the type choice

NowProductPreview — a frozen Workspace → Project → Board mockup, the same whatever the user picks.
ProposedPick “Research” and the preview shows an evidence-review board, not a Kanban. Small, and it makes the type choice feel consequential.

Lower value now. With #1, the first-run path no longer has a “frozen preview before a type is chosen” problem — the type picker's own per-card previews already do this job.

9
Effort: S

One home for the “getting started” story

NowGettingStarted.tsx and the Overview's overview-starter-strip cover overlapping ground with different framing and no handoff between them.
ProposedPre-workspace: choose or create a context. Post-project: the activation checklist (#5). Each does one job and points at the next.

Largely addressed by #1 and #4/#5: Getting Started owns the pre-project story, the Get Started strip owns activation. The Overview's starter strip remains only as the skip-path fallback.

Where it started

Recommendations 1–3 were one coherent change to the wizard, and shortened the runway most. #6 was the cheapest way to help a prospect who isn't ready to commit to setup at all. All three picks below have since landed.
