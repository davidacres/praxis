Handing a Ticket to an Agent

Verified — it works

A ticket goes in; a real agent reads a file in the project folder, edits it, and the change is on disk when the session completes. File access is sandboxed to that folder and gated by tool mode. Tool use pauses for approval.

Proven two ways: an automated end-to-end test with a scripted agent that runs in CI on every push, and one run against a real model (Claude Code) that took a failing test suite and made it pass.

How it was tested 01

Two layers. The first proves the plumbing carries a ticket to a file edit and back, deterministically and for free. The second proves a real model does something sensible with the ticket — the half the first can't touch.

In the normal suite

Scripted agent, end to end

e2e/aiCodingTask.spec.ts · 3 tests · ~10s · no model

  • The agent is a real ACP subprocess — real SDK, real wire framing — that does one fixed edit through Praxis's own fs/read_text_file and fs/write_text_file handlers.
  • Full tools: session reaches completed, the file on disk is changed, node -e proves the fixed function runs, git shows exactly one modified file, the edit renders as a red/green diff.
  • Read-only: the write is refused by the host, the file is untouched, the session says why.
  • Turn recording: a first turn plus two follow-ups; each records its reply once and carries the earlier answer forward.
Part of the 197-test functional suite. Runs on every change.
Opt-in only

Real CLI agent, real model

e2e/aiLiveAgent.live.spec.ts · --project=live-agent

  • Drives claude-agent-acp against a real model on whoever's account it is signed in to. Spends money; takes minutes.
  • The task is small and self-verifying: the seeded repo ships a failing node --test suite; the ticket asks for it to pass.
  • Success is measured by running that suite afterwards — not by reading the agent's prose — and by checking it fixed the source rather than deleting the test.
  • Excluded from every other Playwright project; skips outright without PRAXIS_LIVE_AGENT=1.
Never part of npm run test:desktop. Run it by hand when you want the answer.

The live run 02

The seeded repository: a slugify() that only lowercases and hyphenates, and a four-case suite it fails three of — repeated spaces, surrounding whitespace, punctuation. The ticket named the three faults and said: make the suite pass, don't touch the test file.

agent claude-agent-acp state completed steps 6 time 45.6s suite 3/4 failing → 4/4 passing files slugify.js only 
# the agent's move, in order
1  read slugify.js and slugify.test.js
2  ran `node --test`  → baseline: 3 failures confirmed
3  rewrote the transform
4  ran `node --test`  → 4/4 passing

# what it wrote
function slugify(title) {
  return title
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, ' ')  // punctuation + repeated spaces, one rule
    .trim()
    .replace(/ /g, '-');
}

The three separate defects the ticket listed, collapsed into one substitution. It ran the suite itself for a baseline before editing and again to confirm — unprompted.

A real bug the testing found 04

Not the flow itself — the conversation memory underneath it.

An agent turn never recorded its reply as a conversation event. fixed in aa271de

The reply lived only in responseText, which the transcript still showed, so it looked cosmetic. It was not: the prompt for the next turn is built from message events, so the agent lost its own answer to the first turn the moment a user asked it to continue. The follow-up path papered over this by re-appending the prior reply on the way in — which runs too late to reach that prompt, and from the second follow-up on left a duplicate. Both paths now record the reply when the turn ends, and the retroactive flush is gone.

Why the live test can't leak into a normal run 05

It spends money, so it is fenced three ways — each verified, not assumed.

    Excluded from every other project.The functional and theme-regressions projects ignore *.live.spec.ts; it matches none of the themes patterns. Confirmed: collected by no other project.
