Project Details & Board Surface

FX-BF-008 · Praxis desktop

The right pane follows the theme, and the board can opt out

Selecting a project used to open a second navigation panel painted on an opaque slab. It now opens a compact, theme-aware project-details inspector; ticket details get the same treatment; and any board whose surface material hurts legibility can switch to a plain background from its own settings. Removing boards and starting from an empty workspace are handled where the user already looks.

Shipped owner @praxis/desktop-renderer + @praxis/core board prefs

Project details

An inspector, not a second navigation panel

The right pane's ProjectHome was a full-width card layout squeezed into a narrow column, with its own opaque background and a “retained PROJECT.md” banner that only ever appeared here. It is now a stack of borderless, transparent sections that inherit whatever theme and surface-pack material the pane behind them paints.

  • Identity header — name, KEY · TYPE · created, and Edit as a pencil icon in the top-right that swaps to Cancel / Save.
  • Status chips — repository state (Git repo / No repo / No folder), default tool mode, linked-board count.
  • Brief — a filled / total completion meter over a checklist of every field; a check and the value when filled, a muted label when empty. Edit mode expands to the full form.
  • Workspace — folder path plus detected languages, frameworks, and manifests as tags.
  • Planning sources — linked boards as compact rows, each with a trash control to remove it from the project.
WasOpaque --bg card · bordered panels · “Open plans board” button · text “Edit” link · retained-file notice
NowTransparent sections on the pane's material · pencil Edit in the header · chips + brief meter · no notice

Ticket details

The detail pane inherits the surface

.detail-panel painted a solid --bg fill over the themed pane. It is now transparent, so the surface pack—texture, watermark, tint—shows through behind the ticket fields, matching the project-details view. The expanded reading mode keeps its own solid fill so long descriptions stay legible.

Board appearance

Plain background, per board

A strong surface material can make dense columns hard to scan. Board settings gains an Appearance section with a Plain background toggle. When on, that board's pane drops the material—texture, watermark, tint, glass, accent glow—and sits on a flat elevated fill. The colour theme is untouched.

  • New optional preference BoardColumnPreferences.plainSurface in core, persisted per board and restored on relaunch.
  • The renderer marks .board-shell with data-plain-surface; .pane-main:has(…) neutralises the surface layers.

Board lifecycle

Remove a board from where its list lives

The trash control on the sidebar Boards list now shows for every connection-backed board, not only plan boards. Demo boards have no connection and stay put. “Remove” means different things per backend, so the action is routed:

Board backendActionEffect
User workspaceuserWorkspace.deleteBoardDrops just that board; the connection keeps its others.
Live folderconnection.removeThe connection is that one board, so it goes too.
Jira / GitLabconnection.removeTrackedBoardUntracked from a shared connection; nothing remote is deleted.
  • Deleting the board that is currently open navigates away first.

Empty state

No boards leads somewhere

When the workspace has no boards and none is selected, the centre pane showed the AI session composer—which can do nothing without a board. It now shows a No boards state with a Create board button that opens the Connections screen.
