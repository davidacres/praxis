The token contract 01

Four layers resolve onto :root, each one narrower than the last. A component never reaches past this — it styles through a token, and the token is what a theme gets to move.

LayerSelectorSetsConstant across themes
Base :root Fonts, radius, space, the type scale, every --tone-* Yes — these are the same in all 26
Mode [data-mode] The surface and text ramp: --bg, --text, --border, --danger No
Accent [data-accent] One hue: --accent and its hover, contrast, soft and border variants No
Theme [data-theme] A complete named palette — ramp and accent together No
Derive, don't duplicate. Tokens that depend on the accent resolve lazily against it — --focus-ring: var(--accent), --wf-agent: var(--accent), --success: var(--tone-green). Adding a theme therefore means setting the ramp and the accent, and nothing else: 26 palettes exist with no per-theme override for focus, workflow lanes or status.

The renderer's copy of the settings defaults is hand-maintained, because core is CommonJS and pulls chokidar and markdown-it into anything that imports it. An appearance token added in core must be mirrored in settings/settingsDefaults.ts or it silently reads as undefined.

--tone-tour is the newest and the most deliberate. An annotation drawn over the app has to be legible as not part of the app; picking any existing token would have made the tour look like a control.

Type 04

Seven steps, derived from where the app's type already sat rather than from a ratio. Twenty-six distinct sizes had accumulated — including 10.5, 11.5 and 12.5 — which is a continuum, not a hierarchy a reader can learn.

Scale rendered at its own value
--text-xs11pxLabels, eyebrows, metadata — the floor
--text-sm12pxSecondary body, list rows, captions
--text-md13pxThe working default — most of the app
--text-lg15pxEmphasis, card titles
--text-xl18pxSection headings
--text-2xl22pxPage headings
--text-3xl30pxDisplay figures
11px is the floor for anything a person reads. All 29 declarations below it belong to .praxis-preview-* — the scale-model mockups on the theme cards, which draw the whole app at roughly a fifth size. Their 5–7px text is a drawing, not copy, and is deliberately left alone.

The band that made this necessary

The dense 11 / 12 / 13 band carries most of the interface, so a stray 11.5 sits invisibly between two real steps and quietly breaks alignment with everything around it. An early draft of this scale jumped 11 → 13 → 15 and erased the 12px band that some 120 declarations were using; the shipped scale keeps it.

Geometry 05

Radius carries meaning here: it separates an inline control from a panel from a floating surface. Spend it by role rather than stamping one value everywhere, which flattens the hierarchy it was meant to express.

Sibling groups are laid out with flex or grid and gap, taking their rhythm from this scale, rather than per-element margins that collapse or double. One fixed dimension sits alongside them: --titlebar-height: 40px.

Patterns 06

Four recurring pieces of chrome. Each one is a single rule the whole app shares, which is what keeps a fix in one place from being undone in another.

Keyboard focus

One global :focus-visible ring, last in the stylesheet so it wins on source order against component rules that tint a border instead. :focus-visible rather than :focus, so pointer clicks stay quiet.

Focus ring 2px solid var(--focus-ring), offset 2px

focused

A component may not swallow the ring with a bare outline: none. That invariant had eroded once already — 26 resets against 15 :focus-visible rules, while :hover was styled 91 times. It is invisible in a screenshot and only bites people driving the app from the keyboard, so it is held by an e2e test that tabs 25 stops and asserts each one paints something. Eleven resets survive, each paired with its own visible treatment.

An annotation must not look like a control. Dashed, in a hue used nowhere else, and never taking pointer events — the highlighted control stays clickable, so the tour can't trap anyone. Both properties are asserted, along with the callout's tour-coloured top edge; the ring's geometry is asserted to actually enclose its target, which is how a lagging transition was caught pointing at the previous control.

Empty states

A column: icon, one line of text, and — where an action makes sense — the button that fills it. A placeholder that only describes its own emptiness wastes the moment a person is most ready to act.

Dialogs

Twenty-three window.confirm and window.prompt calls used to hand the user an OS chrome that ignores every token on this page. They now route through one in-app DialogHost returning promises, at min(420px, 90vw). None remain: the only match left in the renderer is the sentence in the module that replaced them.

Invariants 07

The rules worth knowing before changing anything above — each one is here because it broke once.

  1. 01
    Style through a token, never a literal. A literal is invisible to all 26 themes. The type scale exists because 26 distinct sizes had accumulated where seven were meant.
  2. 02
    The accent is brand and primary action. Nothing else. Anything that means "running", "selected" or "annotated" takes a tone. Three meanings on one hue made a dashboard unreadable at a glance.
  3. 03
    Nothing readable goes below 11px. Only the fifth-scale mockups may, because their text is a drawing.
  4. 04
    Order shorthands after the longhands they reset. A border-top above a border shorthand is silently wiped. That is exactly how the tour callout lost its hue — no error, no failing test, just an unbranded panel.
  5. 05
    Define every token on the base :root before a theme redefines it. The status aliases were referenced across the stylesheet but never declared, so status dots and health chips rendered colourless in every theme.
  6. 06
    Look at the rendered output, not just the test result. Every visual regression here passed a fully green suite: a node label wrapping at 11px, an empty state collapsing into a column, a ring pointing at the wrong control. Where a visual property matters, assert it geometrically — and prove the assertion can fail before trusting it.
